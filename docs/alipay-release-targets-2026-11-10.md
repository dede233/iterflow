# 支付宝发布目标与平台表单联动 · 2026-11-10

## 范围与行为

用户追加支付宝小程序发布平台，并要求 PC Web 才显示访问地址、小程序才显示 AppID。本轮仅本地开发与任务隔离测试，不部署 TEST/正式，不访问线上数据库，不推送/合并或创建 tag/Release。

- 发布目标目录新增 `ALIPAY_MINI_PROGRAM`（支付宝小程序），与 PC Web、微信小程序并列；创建、编辑、首次发布选择、发布后补记、版本覆盖范围与实际发布记录均支持。
- 创建/编辑表单按平台显示单个选填字段：PC Web 为访问地址，小程序为 AppID。切换期间保留尚未保存的输入；保存时不适用字段提交 `null`，防止隐藏数据被误保存。取消不写入。
- 编辑表单只取可编辑字段，修复原先 `Object.assign(item)` 将 ID/时间戳等只读响应字段带入 PATCH、被 `extra=forbid` 拒绝的问题。
- AppID 仍为选填、不要求 AppSecret、不调用支付宝发布 API；平台字段只记录实际覆盖范围。版本验收/发布门禁、CAS、RBAC/DataScope、唯一 Release 和实际上线时间不变。
- 历史发布快照不随目录编辑而改写。旧数据不自动清空/转换；仅用户保存目录时处理不适用字段。后端继续兼容旧客户端独立更新选填字段。

## 契约与迁移

开发契约 `spec/openapi-development.yaml`、Pydantic DTO、SQLAlchemy 约束和生成前端类型同步新增枚举；已发布契约和历史迁移不变。

- PostgreSQL：`0017_target_releases → 0018_alipay_targets`，替换目录、批次目标两项平台 CHECK。
- MySQL 5.7：`mysql57_0015 → mysql57_0016`，替换对应两表的 INSERT/UPDATE 共四个 domain trigger；保留完整性开关检查、布尔值、完成记录成组校验。删除触发器、不可变记录触发器和其他触发器不动。
- 不新增表/列/权限，不重写业务行。MySQL preflight 新应用要求 0016，显式旧基线预检保留 0015 兼容。
- 降级前先检查目录及批次目标两张表：任意支付宝目标或历史快照存在就拒绝，绝不删除/改写历史以满足旧枚举。

## 后续部署及回退边界

当前 TEST 仍 Web `0c12952` / API、worker `097b2dd` / `mysql57_0015`，正式仍 `5401215` / `mysql57_0012`；这是上一轮已确认基线，本轮没有重新连接远端核验。

此增量需要 API/worker/Web 配套更新和迁移，不能只部署前端。后续获得环境部署授权后，应先备份、隔离恢复迁移演练及数据保留比较，停写后执行 DDL，再更新应用并核验运行账号权限/触发器及两平台旧数据。

MySQL DROP/CREATE TRIGGER 会隐式提交，迁移期间必须停写；中途失败保留维护状态并前向修复，不自动启动旧应用或恢复数据库。出现支付宝目录或历史快照后，旧应用的输出枚举无法正确读取，禁止直接回退到不支持支付宝的旧镜像；优先前向修复或保留新枚举支持的兼容补丁。数据库降级仅在两表均无支付宝记录并重新核实保护条件后另行安排。
