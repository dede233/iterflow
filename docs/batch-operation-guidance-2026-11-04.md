# 批量操作指引优化（2026-11-04）

用户反馈现有批量操作不清晰、指引不足。本次在现有分支上统一调整反馈列表、需求列表和版本需求清单共用的批量组件；基线 `c1e78f4`。仅本地前端实现和合成 API 验证，不部署、推送、合并或访问真实数据库。当前 TEST 仍为 `c0f68e1` / `mysql57_0012`，正式仍为 `96ba96e` / `mysql57_0011`。

## 交互与边界

1. 入口明确为“批量处理反馈/需求”，版本清单只处理关联需求，不会批量发布版本。
2. 第一步选择操作和记录：不默认执行某个动作；操作卡片展示适用阶段、执行人和影响。确认需求明确区分待确认进入待开发与其他阶段重新确认内容；验收通过明确后续仍需发布。
3. 明确当前页与当前版本筛选清单两种范围，显示已选数量及50条上限，提供选择当前范围/前50条、清空选择。记录显示业务编号、标题和中文阶段。
4. 第二步读取最新数据核对，显示可执行/跳过数量、具体角色/阶段/内容确认/设计阻塞与详情入口。主按钮包含实际动作和条数；全阻塞时不给执行入口。返回调整后必须重新检查。
5. 关闭反馈与管理员代操作分别说明必填原因；选填说明保留。通过原批量接口提交检查所得revision，由服务端逐项执行并检查全部门禁。
6. 结果页保留本次检查快照，汇总成功/失败/跳过；未知响应单列“待核对”，引导核对详情。没有重试成功项或直接重放本次请求的入口。
7. 提交期间父列表刷新不能清空已发送请求的快照或解除提交锁；账号变化仍隔离并关闭旧上下文。结果与业务名称来自检查时快照。
8. 手机使用全屏弹窗，步骤条及底部按钮保留，正文独立滚动；次要按钮不逐字换行，主操作单独成行。

无 API shape、迁移、RBAC、状态机或事务规则变更。反馈仍仅支持受理/关闭，需求仍仅支持确认/开始开发/提交验收/验收通过；不增加批量删除或发布。

## 已发现问题与处理

- 原提交期间若父列表刷新，会废弃写请求回包并重新允许操作。已增加提交状态保护和上下文快照，保留成功/失败或待核对结果。
- 预检原取最新revision却保留列表旧标题；已使用详情返回的最新标题，并保留到结果页。
- 首轮组件测试沿用“全部阻塞时禁用提交按钮”的旧断言；新交互改为隐藏执行入口并说明处理方式，已按该行为调整断言并通过完整回归。
- 首次浏览器测试直接勾选 Element Plus 隐藏的原生 input 超时；改为点击实际可见label并断言checkbox语义状态，保留首次日志，没有force点击。
- 手机截图发现既有全局弹窗及按钮flex样式覆盖局部布局，导致次要按钮逐字换行、步骤条被焦点滚出。已为本组件限定布局覆盖，正文单独滚动，步骤切换用preventScroll并归零正文滚动位置；补充可见范围和按钮文字单行断言。
- 手机步骤圆形标记在列布局下被挤窄，已明确26px宽度并重新检查截图。
- 最终选择页截图曾出现已选背景但勾号未画出的瞬间；专项采集DOM与计算样式确认是Element Plus过渡动画取帧时机。等待实际动画完成后，4条记录均为选中状态、蓝色背景及白色勾号；未添加多余产品CSS覆盖。诊断证据保留于 `browser-checkbox-diagnostic.log`，浏览器用例补充稳定截图与可见选中标记断言。
- 第一次全量浏览器命令误包含2项需要隔离数据库的真实后端用例。发现后在这些用例运行前中止：34项通过、2项被中断、284项未运行，日志 `browser-final.log` 保留；未提供真实API凭据，未执行真实后端用例。改为明确排除这2项后运行318项合成API回归，此中止不计为产品失败。
