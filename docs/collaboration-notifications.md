# 协作通知运行说明

本功能尚未部署。所有验证在隔离数据库和本地 SMTP 测试收件箱进行，未使用真实邮箱或生产密钥。

## 运行方式

API 与业务服务只在事务中写入 `sys_collaboration_event`，不连接 SMTP。独立进程运行 `python -m app.tasks.mail_worker`；一次处理可使用 `--once`。Compose 新增 notification-worker，与 API 共用镜像和环境。站内通知也依赖该 worker；既有发布事务中给反馈提交人的站内上线通知继续原子写入，worker 不再重复创建。

SMTP 默认关闭。配置见 `.env.example`：SMTP_HOST/PORT/SECURITY/USERNAME/PASSWORD/FROM、APP_PUBLIC_URL。生产要求 TLS 和 HTTPS 站点地址；非生产启用 SMTP 必须设置具体地址白名单 SMTP_ALLOWLIST。密码只来自环境配置，不写数据库、审计或异常文本。本次没有提供、读取或测试真实 SMTP 配置。

## 用户设置

个人中心提供全部关键通知、仅待办与上线（默认）、关闭邮件。未验证地址不发送业务邮件，站内通知仍保留。输入邮箱后请求六位验证码，15 分钟有效，60 秒发送间隔、最多五次错误尝试；验证成功才更新用户邮箱。请求后账号修订发生变化须重新申请。邮箱由管理员改变后旧验证自动失效，原地址待发记录不重定向。邮件地址验证与业务确认完全独立。

升级不会补发旧事件；新验证邮箱不补发验证前的业务事件。业务事件覆盖接收人加入、受理/转交/关闭/重开/转需求、环节分工、内容重新确认、设计/开发/验收/暂停/取消、版本归属变化和实际上线。需求关联反馈的关注者接收以反馈为入口的简要进度，不暴露没有访问权的需求内容。

## 投递与排障

事件扩展为每个用户的 SITE/EMAIL 记录，唯一键为事件/用户/渠道。事件扩展事务提交前不可见；投递前再次检查有效账号、权限码、数据范围、当前接收或参与关系、邮箱和偏好。消息只含对象编号和进度摘要，邮件采用纯文本，附站点详情入口，无登录令牌或内容快照。

投递状态：PENDING、SENDING、SENT、RETRY、UNCERTAIN、FAILED、SKIPPED。先提交五分钟发送租约再连接 SMTP；进程重启可恢复过期租约。暂时错误指数退避，最多五次；永久 SMTP 拒绝终止自动重试。超时/断连单独标记结果不确定，固定 Message-ID 降低重复风险，**不保证 SMTP 严格一次送达**。SMTP 未启用时不消耗尝试次数。授权撤销、偏好关闭、邮箱变化或白名单不匹配记录为跳过。

个人中心中具备 `sys.user.edit` 且拥有有效超级管理员/研发负责人资格者可分页查看脱敏投递状态；仅当前 FAILED 可按已见尝试次数手动重试，写审计，重新检查权限。SENT/SKIPPED 不允许重试，防止随意补发历史通知。记录保留失败码，不保留 SMTP 错误正文、凭据或验证码。验证码由服务端秘密与随机挑战标识派生，明文仅在发送时构造。

排查顺序：检查 worker 进程 → 待处理事件/投递积压 → 账号与参与关系 → 邮箱验证/偏好 → SMTP/白名单 → 失败码。实际环境连通性、发件身份验证及真实发信需后续环境授权与验收，不是本地验证结果。
