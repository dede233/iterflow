# 小程序按品牌统一管理（2026-11-10）

用户在录入充电宝用户端目标时明确：一个品牌为一条小程序目标，在其中维护微信和支付宝 AppID；发布时分别勾选平台，分别保留实际上线时间。目标仍只记录发布覆盖范围，不成为版本发布门槛。

## 方案与边界

- 管理入口选择「小程序 / PC Web」。小程序一张表单维护品牌名称、编码及微信、支付宝的启用状态和 AppID；PC Web 继续仅维护访问地址。
- 复用每个平台已有的发布目标和不可变快照，以共同编码前缀及明确的平台后缀 `_WX` / `_ALIPAY` 形成品牌。只组合同系统、相同名称且后缀与平台匹配的记录；旧目标保持原 ID、记录和时间，不按名称猜测合并。
- 新增原子品牌保存接口，一次提交全部平台及编辑时的完整成员 ID/revision；任一冲突或失败整体回滚。并发新增平台、过期成员清单、跨系统目标、重复平台和编码冲突均拒绝。停用保留数据，不删除平台历史。
- 旧独立目标可在编辑后显式采用品牌编码，保留原 ID；新增另一平台时与旧目标同事务保存。已有多平台品牌不允许通过旧单平台修改接口拆开修改。
- 发布和补记仍使用既有平台目标 ID，分别勾选、分别记录时间；一个平台已发布不会自动勾选另一平台。唯一 Release、原上线时间、需求状态、通知和历史快照保持原规则。
- 无数据库迁移、新实体或权限；只调整当前开发契约和必要前后端。使用本任务新建隔离数据库验证，不自动推送、合并或部署。

正式环境目前只通过正常界面保存一条「开电 / 微信小程序」：编码 `POWERBANK_KAIDIAN_WX`，AppID `wxe239d5068a950860`。用户纠正模型后已暂停，其余 16 个平台未添加。该条可沿用原 ID，后续在新表单补齐支付宝；没有删除或重建它。

### 失败和修正

- 初轮 PG 从仓库根目录运行导致 Alembic 路径错误，未完成建表；修正 backend 工作目录后 25 项通过，追加并发场景后 9 项通过。最终契约命令遗漏 `PYTHONPATH=.` 导致 2 个收集错误，补齐后 29 项通过。Ruff/Mypy 初轮路径或配置入口问题修正后通过。
- 初轮浏览器 5 项通过、3 项失败，原因是自动化点击 Element Plus 隐藏的原生 checkbox；改为点击用户可见标签，并保留勾选/禁用断言，最终 11 项通过。未放宽产品门禁。
- Docker 初轮 ready=503，原因是任务运行参数使用不可解析的 `host.docker.internal`，且遗漏绝对上传目录。改用任务专用网络和 `/app/data/uploads` 后通过；没有修改产品来绕过健康检查。
- 自查补齐失败加载时清空旧系统列表、异步保存时核对当前系统，以及新平台缺 AppID 返回契约已有 409 错误；最终表单三尺寸及 PG/双 MySQL 冲突回滚复核通过。
