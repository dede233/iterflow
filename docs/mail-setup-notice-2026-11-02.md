# 邮件通知引导弹窗

2026-11-02 用户要求根据邮箱绑定状态展示提示，点击“我已知晓”后不再弹出，并明确选择按账号保存、所有设备生效。本次为本地实现与验证；未推送、合并、部署或修改测试/正式服务器数据库。

## 展示与操作规则

| 情况 | 行为 |
| --- | --- |
| 已登录，邮件服务启用，邮件偏好非 OFF，尚未知晓，邮箱未验证 | 显示“邮件通知已上线”弹窗 |
| 当前邮箱及待验证邮箱均为空 | 提示未绑定，主按钮“去绑定邮箱” |
| 已填写邮箱或存在待验证地址，尚未验证 | 提示未完成验证，主按钮“去验证邮箱” |
| 已验证、已知晓、主动关闭邮件、SMTP 未启用 | 不弹窗 |
| 正在个人中心设置邮箱或必须修改初始密码 | 不打断当前操作；离开个人中心时重新读取状态 |
| 状态读取失败，或旧 API 尚无知晓字段 | 不推断为未绑定，不阻断业务 |

“我已知晓”成功后写入当前账号的知晓时间，其他设备下次读取设置时也不再提示。重新登录、更换浏览器、清空浏览器存储或修改邮箱均不重置知晓状态。账号之间互不影响；不使用 localStorage 保存该标记。

关闭按钮或 Escape 只关闭本次会话内提示；刷新或重新登录后仍可提示。“去绑定/验证邮箱”打开个人中心邮件通知区，不自动发验证码、不代表已知晓。已验证账号即使没有点击知晓，也不弹出。

保存中禁用重复点击；失败保留弹窗并显示重试说明。revision 冲突时重新读取设置，让用户手动再次确认，不自动重放写请求。旧账号响应、页面离开后的迟到响应不更新当前提示。

## 实现与权限

- `GET /me/mail-preferences` 新增 `notice_acknowledged`。
- `POST /me/mail-notice/acknowledge` 只接受邮件设置 revision，操作对象始终来自当前登录身份，不接受目标账号。普通用户无需业务角色或管理权限。
- 使用既有用户/偏好行锁与 revision CAS；首次知晓递增 revision、记录 UTC 时间并写 `MAIL_NOTICE_ACKNOWLEDGED` 审计。同一最新 revision 重复知晓不重复审计；旧 revision 返回 409。
- 不修改邮箱、邮箱验证、通知偏好、需求状态，不创建通知事件或发送邮件。
- 开发契约及生成类型同步；已发布 OpenAPI 快照不变。
- 前端由 `MailSetupNotice.vue` 挂载到登录后布局，个人中心保留完整邮件设置入口，支持手机、平板与桌面。

## 旧数据与后续升级/回退

追加 PostgreSQL `0013_mail_notice`（上游 `0012_multiple_acceptance`）及 MySQL `mysql57_0011`（上游 `mysql57_0010`）。只为 `sys_mail_preference` 添加可空 `notice_acknowledged_at`，旧行默认 NULL；不改写历史邮箱、验证码挑战、偏好或 revision，不把旧账号自动标为已验证或已知晓。

MySQL 启动检查接受新的 head 并检查新增列；迁移入口仍允许从 0010 升级，旧 head 不能运行新版后端。PostgreSQL 保留带时区时间，MySQL 使用 UTC DATETIME(6)。已有表、触发器数量及业务关联不变。

此补丁尚未部署。后续需按测试先行流程取得对应部署授权，备份并核对运行基线，先迁移，再更新配套 API/worker，最后更新 Web。新 Web 在旧 API 缺少知晓字段时暂不提示，避免调用不存在的写接口。

可先回退兼容的 Web 并保留追加列。旧 API/worker 的 MySQL 启动检查不接受 0011，不能直接切回旧后端；需前向修复或经验证的兼容包，不手改 Alembic 版本号，也不为回退界面自动降级数据库。如果尚无知晓记录，可在隔离演练中验证退回上一 schema；一旦存在知晓记录，两条迁移都拒绝有损 downgrade。MySQL 多步 DDL 不能整体事务回滚，较早迁移拒绝降级前，较新迁移可能已经完成；不要把“报错”视为 schema 未变化，不自动恢复真实备份。
