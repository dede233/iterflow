# 发布目标改为覆盖记录（2026-11-10）

## 本轮确认与边界

用户看过 TEST 后反馈，发布目标应在发布时或发布后勾选已经发布的小程序 / PC，方便管理；进一步明确“目标只用于记录发布覆盖范围”。本次规则替代 2026-11-09 的“先建计划、首次全部完成才整体上线”。

在 `codex/multi-target-release` 基于 a5e5a9b 本地实现。未访问或部署 TEST/正式环境、未推送/合并/tag/Release、未连接真实数据库。TEST 最近部署事实仍是 2b9fd16/mysql57_0015，正式最近部署事实仍是 5401215/mysql57_0012，本轮没有重新核验服务器。原八项远端 CI 不代表本增量通过远端 CI。

## 最终行为

- 版本恢复“发布版本”入口，仍检查权限、版本 revision、需求验收/内容确认及同系统归属。发布时可多选已经发布的小程序或 PC，也可不选。无需建立目标计划或填写传统发布原因；目录还有未选目标也不阻塞上线。
- 发布时选择目标与唯一 Release、版本/需求/反馈上线、通知、审计在同一事务提交；任何一步失败完整回滚。
- 已发布版本可“补记已发布目标”，一次多选最多50个新目标，填写共同的实际上线时间及可选说明/凭证。不同时间分次登记。只增加覆盖及审计、更新版本 revision，不改原 Release/上线时间、需求状态或重复通知。
- 已记录目标勾选且禁用，避免重复登记；同系统启用目标可选，重复、跨系统、停用、旧 revision 由后端拒绝。筛选仍按原查看权限与 DataScope。
- 详情直接显示覆盖数量和名称，可折叠查看登记人、实际时间与记录时间；发布记录继续支持按具体目标筛选。兼容 PC 与 375px 手机操作。
- 保留人工记录性质，不调用微信或 PC 平台自动发版，不保存 AppSecret。保留成功记录不可改写/撤销的原规则。

## 接口和旧数据

- 仅更新开发契约及生成类型/中文文档；发布快照不变。
- 原 `POST /versions/{id}/publish` 增加可选 `target_ids`。
- 新增 `POST /versions/{id}/release-coverage`：`version_revision`、唯一非空 `target_ids`、带时区 `released_at`，可选 `system_id/notes/evidence`；201 返回 `ReleaseBatchOut`。沿用发布权限与版本范围，不新增 permission。
- 复用三张已有目标表，以 COMPLETED 行保存覆盖历史，不新增 migration，不修改已有 migration/触发器。版本→批次→目标的锁顺序与 CAS 保留。
- 原计划写接口保留响应契约，但返回409和刷新使用新入口的明确提示；不再允许旧客户端生成计划或触发目标收尾上线。查询接口继续读取全部旧批次。
- 正常发布 / 补记时原子关闭旧未完成计划，完成行完全保留；未完成行仅标记“不计入已发布范围”，不造成功记录。发布失败时关闭旧计划也回滚。
- 旧不可逆冻结标记不清空，已有部分实际发布的内容保护继续保留，正常发布入口可用，不要求其他目标完成。新流程不产生部分发布冻结。
- 旧无系统的已发布版本在补记时显式指定目标系统，后续须一致；不重写旧版本/需求归属，不推断旧覆盖。

## 首次失败和修正

- 首次 PG 专项43通过、2失败：测试直接构造补记 DTO 时传了 datetime 对象，而既有 OffsetISODatetime 要求 ISO 字符串。改成模拟真实HTTP输入后，相关回滚/并发及全量通过；未放松时间校验。
- 首次前端506通过、1失败并伴随递归异常：切换详情使旧弹窗在 state 暂空时短暂挂载业务系统选择器。只在弹窗打开且状态已就绪时挂载后，507全部通过，无未处理异常。
- 首次浏览器19通过、3失败：两项使用精确“发布说明”定位未匹配带必填标记的输入；补上明确 aria-label。另一项375px在开发热更新期间点击节点不稳定，冻结页面代码后整批22通过，最终增加真实勾选断言的6项也通过；不以不稳定首轮宣称通过。
- 本地 AMD64 MySQL 官方入口在 ARM 执行时初始化进程异常退出；standard 保留已初始化卷改用同镜像直接 mysqld 成功，portable 原卷初始化不完整，保留错误日志后在新的任务卷直接初始化再启动。一次临时端口释放冲突等待后启动，未修改现存 Preview 或共享服务。仍使用真实5.7.44及原两种配置，没有降级数据库门禁。
- 类型检查发现事件参数缺类型、模板可空对象，已修复；末次静态检查发现新增注释超长，仅缩短注释。最终检查通过。
