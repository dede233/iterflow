# 发布记录与版本详情抽屉

2026-10-13，基于 master `6bdf8017a243a4f47441837fe1c40ebe3fadec28`，在 `codex/release-detail-drawer` 修复发布记录入口未沿用详情抽屉的问题。本文件描述开发分支的功能和本地验证，不代表8444或8443已部署。

## 操作方式

- 发布记录列表的“查看详情”打开发布记录抽屉；PC端也可点击记录行。
- “查看版本”打开版本抽屉，不离开发布记录列表。
- 发布记录中的所属版本、版本中的“查看发布详情”在同一抽屉切换，可“返回上个详情”。重新打开列表记录会重新建立详情路径，不保留上一次路径。
- “关闭详情”、右上角关闭和Esc退出抽屉；原列表分页、已应用筛选与滚动位置保留。
- 手机宽度低于768px使用全屏抽屉；桌面、平板保留侧边抽屉。
- 顶部“新标签/全屏直达”沿用原版本入口文案，实际行为是在当前标签打开独立完整页；返回目标只接受现有白名单列表条件。直接访问详情URL和通知中的详情链接仍可打开独立页。
- 发布记录保持只读。版本编辑、状态推进、需求清单与发布操作复用原详情组件，版本更新后刷新所在列表。

## 实现边界

修改共享抽屉、发布/版本列表与详情、详情返回上下文和对应前端测试。共享组件按实体类型和ID挂载详情组件，切换时销毁旧实例并按需加载；重复跳往已在详情路径内的对象时回退到该对象，避免循环堆叠。

发布与版本查看权限分别校验，没有版本权限不显示版本入口、不读取版本信息。版本元数据因403/404或网络失败而不可用时，发布记录继续可读；显式查看不可访问版本时保留错误和重试入口，可以关闭回到原列表。后端接口继续执行RBAC/DataScope，客户端不使用目录接口补足权限。

没有后端、契约、数据库迁移、角色权限、状态机、revision CAS或发布事务改动；历史契约、迁移、tag和Release保持不变。
