# 测试环境保留与后续更新流程

测试项目为 `iterflow-acceptance-20261012-753ebd`；配置在服务器 `/opt/iterflow/acceptance/iterflow-acceptance-20261012-753ebd`，数据库、附件和 Redis 各使用该项目独立的 dbdata/uploads/redisdata 数据卷。现有测试账号及数据保留，后续清理或移除须有新的用户明确指令。服务器 state.retention.keep 与 cleanup_hold 已记录保留要求。

后续每次已授权更新依次执行：

1. 按当前开发契约实施，完成相应本地测试、真实数据库回归、构建和复查，以及当次发布适用的 CI 门禁。
2. 记录源 commit、镜像摘要和迁移清单，仅更新8444独立测试项目。已有测试库按正式迁移路径升级，不重复初始化账号、不通过清库制造验收通过。
3. 按变更范围执行多账号、多角色、权限与 DataScope、revision CAS、业务主链及事务等必要验收，并记录实际结果。必要测试失败不得跳过，先修复并重新验证受影响用例。
4. 测试门禁全部通过后，再按当次更新授权范围部署8443。正式部署前备份正式数据库与附件、准备回退方案，并确认正式环境的实际数据库条件。尽量使用测试通过的相同应用镜像；如重新构建或修改产物，需重新核对和验证。
5. 正式更新后验证健康、关键业务和数据保全，记录实际版本与部署结果。测试环境继续保留供后续验收。

测试账号、密码、业务记录和附件不迁入正式环境；测试库与正式库不自动同步。凭据各自通过受保护配置管理，不记录于本文件或部署包中。

当前保留已生效，四个测试服务健康。入口仍由独立临时 Nginx 进程及 runtime 防火墙规则提供，服务器重启自动恢复与定期备份尚未配置，不能将其记为已完成的长期运维保障。名称修复先通过测试环境验收，随后按用户2026-10-12明确授权更新到8443；详见 [修复与验收记录](feedback-reference-display-fix.md) 和 [正式更新记录](feedback-reference-production-upgrade-2026-10-12.md)。
