# 创建弹窗滚动遮挡修复（2026-11-10）

用户截图显示：新建需求操作栏遮住优先级/确认人，后续人员区域出现在操作栏下方。授权继续检查类似 UI 问题并在本地修复；基于 `2a838ef`，不部署 TEST/正式、不推送合并，不改业务规则、API、权限或数据库。

## 原因与范围

之前将整页表单按钮改为 sticky 后，嵌入弹窗时仍让按钮留在同一个滚动容器内。sticky 将底部按钮向上移动，但未从内容区域中预留独立空间，滚动内容可以被盖住、出现在其下方。上轮真实表单验收只覆盖独立页面滚到底部，没有覆盖弹窗中间滚动位置，未发现此缺口。

同类结构有四个入口，已统一修复：

- 需求列表 → 新建需求。
- 反馈列表 → 提交反馈。
- 版本列表 → 新建版本。
- 需求详情 → 创建版本并关联需求。

三个 CreateView 内增加内容区，弹窗通过共享样式形成连续的 flex 高度约束：标题固定、内容独立滚动、操作栏在内容外正常布局。按钮不再使用 sticky 覆盖字段。提示、错误、刷新需求操作均在内容区内；人员展开后仍可滚动访问。完整页面保留原布局，表单提交/取消及版本创建关联行为不变。

反馈/需求/版本编辑弹窗已有独立 footer，未发现相同结构缺口；本轮验证详情抽屉内的查看、编辑、关闭及原筛选上下文，未改其布局。

## 中间失败与修正

- 新回归初版只注入 access token，应用按既有会话规则返回登录，测试被终止；补齐合成 refresh token 后继续。
- 第二轮 5 PASS / 15 FAIL：未等待弹窗入场动画稳定便测量位置，短时位移触发精度断言。增加正常可点击稳定检查后 20 项通过；没有放宽几何阈值或修改产品动画。
- 人员选择初版直接点击 Element Plus 内部 input，被其占位层拦截；改为点击可见选择器 wrapper，实际选择、Escape、取消链路通过。
- 全量单测仍有既有详情夹具捕获后的 jsdom 网络告警；未隐藏日志，最终无失败用例。
