# UI 分阶段优化与本地验收（2026-11-10）

## 授权与范围

用户在 UI 审查后确认按“视觉基础 → 需求列表/详情 → 版本详情 → 表单/移动端 → 首页”的顺序实施，必要时重构 UI。本轮基于 `codex/multi-target-release` 的 `395d968`，只调整 Vue / Element Plus 前端与配套测试。沿用现有业务模型、状态流转、权限、revision、验收和发布规则，不改 API、迁移或数据库配置。

只操作本地开发环境；没有连接或部署 TEST/正式，没有推送、合并、tag 或 Release。真实页面检查使用本机 admin 登录及已有合成记录；除正常登录会话外未新增/修改业务记录，未发邮件。

## 失败与修正

1. 首次阶段浏览器误用默认 8080，连接被拒；改为实际本地 5173 后执行。保留失败证据。
2. 进度从六张详情卡变为步骤+单详情区，旧测试按卡片取文本失效；更新定位并保留人员、确认、权限和写请求断言。
3. 版本概况精简时移除了自动汇总说明，原浏览器测试发现缺失；将说明恢复到需求清单内，16 项复跑通过。
4. 首轮全量单测 505 PASS / 2 FAIL：底部导航旧断言仍要求首页，以及详情权限测试匹配旧模板结构。更新导航断言；详情用外层权限模板包裹来源反馈的两种展示，保持原可见性门禁。增加两项首页测试后最终 509 PASS。
5. 跨页面两项移动测试依赖旧“编号/状态/标题”顺序；改为新“标题/编号/状态”语义定位。另一项人员保存测试在页面刷新期间元素脱离；当时并行执行了详情模板编辑，未改流程代码；保持源码稳定复跑整份 workflow-entry 与 v18-productivity 共 63 项通过。
6. 真实表单补充脚本先未等待路由/登录加载完成，随后误将反馈底栏当作需求的 editor-actions；修正为等待对应底栏并读取可见字段后，8 组全部通过。没有为脚本失败修改产品行为。
7. 全量单测中既有详情组件夹具会输出捕获后的 jsdom 网络连接告警；未隐藏日志，最终没有失败用例。此处不把告警声称为真实浏览器错误。
