## 完成结果（2026-11-12）

### 界面与交互

- 版本清单合并完成数、短进度条和状态筛选，关键词/状态/优先级按需展开；标题与编号合并展示，说明移到清单末尾折叠。按钮尺寸、筛选底边统一，筛选区域使用实例唯一 ID。
- 品牌目标目录改为桌面平台矩阵、手机卡片，支持名称/编码/AppID 搜索与配置筛选；区分未配置与停用。手机搜索独占一行，配置筛选及新增操作等宽、44px 高。
- 版本覆盖按品牌汇总微信/支付宝最近实际上线时间，保留每次登记快照和历史；初始只读取一页时明确标注当前范围。完整加载按页进行，每次最多 50 页，可停止；revision/总数/页边界变化时拒绝混合数据，不从缺失记录推断未发布。
- 需求抽屉按自身容器宽度排列正文和属性；桌面 960px 抽屉以单列阅读为主，完整页面有足够宽度时分栏。新建与编辑统一为标题、描述、验收标准、归属/属性顺序；支持同一编辑器原位全屏，长文本编辑区最大 1200px 居中。
- 需求新建/编辑、品牌编辑、发布补记增加未保存确认和提交中关闭保护，并接通外层抽屉、页面离开及详情切换。表单错误放在字段旁并聚焦首错。既有版本编辑只补提交中卸载保护，未扩大成全站通用草稿系统。
- 反馈/版本列表统一常用与更多筛选、已应用条件标签、标题/编号层级。首页增加内容确认、开发准备、交付验收三组本人参与待办，每组最多 3 项，通过现有服务端角色和权限过滤接口获取；支持各组独立空态、重试与身份切换防串数据。
- 抽屉统一使用“打开完整页面”，移除内层重复返回/关闭；统一基础字号与相关手机触控区域。

### 失败与修正

1. 初轮全量测试在并行开发期间出现 10 项失败（覆盖组件和旧关闭按钮断言），首轮构建出现 TypeScript 推断错误；修正后最终全量通过，首轮日志保留。
2. 品牌空保存测试触发 Element Plus 配置筛选的递归更新。该固定四选项改为有标签和键盘焦点的原生选择器；专项与真实浏览器空保存通过。
3. 手机验收发现原生筛选框被挤成约 38px；改为两行 grid 后复验为 134.5×44px。
4. 全屏新建仍受旧 960px 卡片限制、靠左留白；扩大为 1200px 居中，1440px 下编辑正文实际宽 1158px，复验通过。
5. 独立审查发现外层关闭可绕过内层未保存保护，已补品牌父弹窗和版本补记/详情抽屉/路由链路。新增对应单测；真实补记取消确认保留草稿通过。
6. 补齐既有单测缺失的协作读取接口 mock 和与身份测试无关的后台引导组件 stub，保留业务断言，最终无 JSDOM 网络错误。
7. 验收开始时构建覆盖静态目录，导致旧页面动态资源加载失败；改用独立快照目录并重载后完成验收。另有两次自动化选择器名称不符，读取实际可访问名称后继续，未触发业务写入。
