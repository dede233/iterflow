# IterFlow 更新公告（2026-11-05）

## 本次授权与范围

用户确认按站内更新公告方案实施。公告用于 IterFlow 产品自身更新，独立于业务系统的 Version/Release；不改变业务发布事务、需求状态或邮件偏好。本轮完成本地开发和隔离验证，不自动部署 TEST/正式、不推送合并或创建 tag/Release。

## 行为与人员

- 所有登录且已完成首次改密的账号可查看已发布公告；普通账号不能查看草稿、草稿图片或执行管理写入。
- 仅启用的内置 SUPER_ADMIN 角色管理公告；不凭通配权限或前端隐藏判断，不新增 permission。公告操作有审计，草稿相关审计仅具备公告管理资格和原审计读取权限/范围的账号可见。
- 管理员新建草稿，填写标题、版本标识、上线日期、正文、是否重要；支持富文本、粘贴截图、本地插图、预览。保存草稿不会发布，也不会通知用户。
- 本环境部署验收通过后，管理员明确确认发布。发布时间由服务器记录，页面按发布时间倒序；填写的上线日期只是说明性信息，不触发定时发布。
- 普通更新使用轻量提醒和菜单未读标记；重要更新增加弹窗。与既有邮箱引导错开显示。暂时关闭只关闭本次会话提示；阅读详情或点击“我已知晓”后按账号保存，不再提醒该公告。可在历史列表回看。
- 跨设备读取同一服务器已读记录；另一个已打开的页面在重新聚焦/刷新后同步，不依赖浏览器本地已读缓存，不声称实时推送。
- 公告修正增加 revision，不重置任何账号已读，不改变原发布时间。重大新事项应另建公告。首版不做撤回/删除、邮件群发、评论点赞或自动抓取 Git 日志。
- 图片沿用 StorageService，使用独立 ANNOUNCEMENT_IMAGE 关联及受保护读取接口；不接受外链图片或把物理路径作为业务标识。图片限制与现有编辑器一致。

## 实现和兼容

开发契约先行，新增 /announcements 列表、详情、notice、草稿创建/修正、publish、read、images 接口，生成前端类型与中文接口标签。核心实现为 AnnouncementService、两个公告模型、AnnouncementView、AnnouncementNotice 和账号级 store；图片编辑/预览组件追加明确公告上下文，原需求图片调用保留默认行为。

追加 PostgreSQL `0016_announcements` / MySQL `mysql57_0014` 创建公告与账号已读两表，既有数据不回填、不自动生成或发布历史公告。MySQL 增加 6 个完整性/领域触发器，完整表数 32（含迁移元数据与文件键注册表）、触发器 97。旧迁移快照不改；运行时预检及当前 head 测试断言同步更新。

编辑和发布在锁内校验 revision，并以包含 revision 的 UPDATE 执行 CAS；重复发布返回 409。已读按公告/账号唯一，事务锁避免并发重复插入，不增加公告 revision；已读后重复提交幂等。图片绑定与公告写入同事务，失败沿用上传回滚清理。

发布前必须配套部署 API/Web 和执行追加迁移，不能仅更新 Web。TEST 与正式由现有独立数据库隔离；本轮未访问线上环境。降级前公告表必须为空；已有公告/阅读历史时拒绝有损降级，优先前向修复。
