`POST /versions/{id}/publish/check` 没有 revision CAS；40923 是发布检查结果，不得进入冲突窗。版本关联操作同时校验 Version 和 Requirement revision；409 最小数据不标记冲突对象，因此前端展示请求中的两个 revision，并通过各自有权限的详情 GET 展示两个服务器摘要，不根据中文错误文案猜测对象。服务器摘要不放入 409 `data`。GET 失败 403/404 时显示“该记录已不可访问或不存在”。

目标统一 40910 `data`：`current_revision: int | null`、`current_updated_at: ISO 8601 string | null`、`current_updated_by: int | null`。本地 revision 来自用户实际提交的请求；关闭冲突窗不更新它，只有用户显式重新加载服务器版本才替换表单和 revision。普通业务 409 不触发 revision 冲突窗。

Phase 2 对已读取的对象先比较提交的 revision，再执行当前状态/归属检查；数据库条件更新仍是最终 CAS 保护。因此一次已过期的发布、转换或状态请求返回 40910，使用最新 revision 重复执行不允许的业务操作则保持原业务 409。
