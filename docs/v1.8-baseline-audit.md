## 6. Core business chain

**Feedback → Requirement → Version → Publish → Release**。Feedback 原始输入；Requirement 正式研发需求；Version 只关联 Requirement；Publish 唯一正式发布；Release SUCCESS 历史记录。rollback_notes 列不代表回滚流程。没有 Release 独立 CRUD/状态机。VersionRequirement 为关系权威，current_version_id 为同步查询字段，不以 UI 设置替代关系事务。

REQUIREMENT_LINKED 仅 convert；Requirement/Feedback ONLINE 与 Version RELEASED 仅成功 publish。Manual enums 排除事务终态，非法人工请求422/非法迁移409按既有契约。READY/RELEASED/CANCELED 冻结版本集合。加入需求只把 DRAFT/CONFIRMED 转 PLANNED；移出不自动还原状态。不是所有退回/暂停/取消都强制 reason；schema 已指定传入 reason 的长度。

spec/status-machines.md 的 Requirement/Version 部分是简述，省略一些合法旁路，不是新状态机授权；本表按正式代码完整列出。历史 v0.6.2 评审的状态/测试数字不是当前事实；未发现需改动冻结规则的冲突。

## 12. Cross-domain authorization

convert两种模式授权差异见事务A；Requirement来源Feedback GET要求两域view并过滤Feedback submitter；Version需求GET要求version.view+requirement.view且需求scope独立；关系写双方对象逐一验证。publish/check授权基于publish能力与Version scope，返回冻结契约内的检查和最小阻塞摘要；不能把它复用成普通需求全量读取入口。

Release查询通过Version scope，不要求额外Version view才能读Release；前端Version详情/链接或补充metadata另按version.view，读取失败保持ID。Dashboard release摘要已包含version_no/name（现有正式DTO），Release列表尚无这些字段；未来不能据此无评审复制完整Version DTO到Release。新选择器也只能复用调用者本来可读的列表。

## 13. File authorization

Feedback附件列表/下载需feedback.view+scoped对象+FEEDBACK关系；上传需feedback.create+scope，专用业务路径不是generic sys.file.*语义。generic下载/存在检查限定未附属文件+sys.file.download+文件scope；附属文件不能绕过业务路径。generic删除需sys.file.delete，已引用文件40901，不删除业务历史。

FileService系统生成storage_key，元数据仅file_id关联；50MiB、扩展名/MIME/内容验证；upload数据库失败补偿存储；delete先提交metadata，存储失败可能留孤儿，不留无内容的live DB引用。LocalFileStorage拒绝绝对路径/..并检查resolve后仍在root，S3标准boto3短时URL（默认300s）由授权后生成。没有新做恶意文件扫描/完整安全审计；孤儿回收是潜在运维债，不在本轮实现。

## 21. Deployment separation
