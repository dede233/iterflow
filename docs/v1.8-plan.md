## 2. Frozen Architecture

Feedback → Requirement → Version → Publish → Release；Release record-only/SUCCESS。集中状态机、三事务、revision/CAS/409、对象级 RBAC/SELF/ALL、TEAM reserved、StorageService、安全文件关系、Hash Router `createWebHashHistory(import.meta.env.BASE_URL)` 与 `/#/...`、单响应式Vue工程保持。

新候选若需改变状态机/Publish/关系事务、权限原则、新实体/migration，必须另行产品与架构决策；本计划不批准。不能为了UI显示扩大User/Requirement/Version/Audit范围，不把UI隐藏当后端授权，不自动把deprecated code换成新权限。

候选优先级：P0=已有证据的正确性/安全/发布契约不一致；P1=从当前工作流可证明的效率价值且风险有限；P2=低使用证据、组织/基础设施或平台扩展。**本轮没有发现已证明的产品P0。** 源码能证明缺口，不能证明使用频率、延迟SLA、实际故障率或大数据性能；价值与复杂度为推荐判断。

## 4. Recommended Product Themes

1. **Version日常管理效率**：C0/C1为主，C2为可选责任管理；直接基于当前清单/关系工作流，不增状态。
2. **主链追溯与导航上下文**：C3/C4，处理一项后能回原清单，安全追踪版本/发布。
3. **发布历史可发现性**：C5复用现有日期与版本查询，而非新Release workflow。
4. **通知与首页行动入口**：C6/C7，区分可发现/可执行与已完成的freshness。
5. **管理与审计解释性**：C8/C9，避免把已有中文实体/操作映射、权限Drawer重做一遍。

这是证据聚合后的主题池，不承诺五个主题全部进入V1.8。新页面/权限/模型没有自动授权。

## 5. 产品 Scope 决定与原始推荐

### Approved：C0 + C1 + C3 + C4

建议定位为“版本工作区与主链导航效率”。优先复用当前DTO/list/detail/write，无migration、无新权限、无状态/事务变更。C4先确定query/source约定（本版不保存scroll）；C1选择器只使用本来可读目录，没有view能力降级既有ID，不把写权限自动等同view；C3保持目标读取失败不阻断父详情；C0明确可见进度与全体发布检查差异。

最低验收：两个受限用户SELF/ALL、无额外域/User view、版本冻结与旧revision、旧异步返回、移动选择与长清单、List→Detail→Related→Back/refresh、Hash会话回跳、五视口和既有主链全回归。零新migration/API不是无测试风险。

### 原规划 Alternative（历史评估，本轮未批准）

- 小版：**C0 + C3 + C4**，先不做选择器，保留原ID输入，目录授权成本更低。
- 查询版：**C4 + C5 + C6最小unread-only**；C5优先用有权限的Version选择，C6先不改list shape。若要求无version.view也按Version text检索或完整通知分页，先决策新契约与兼容。
- 管理解释版：**C3 + C8**，目标集中只读追溯与审计展示，适合管理员实际反馈优先的情形。
- **C2** 只有User lookup/分配权限路径明确后再作为增量；**C7** 依赖C4且只导航已有能表达的筛选；**C9** 需要管理员真实使用证据，不混入主推荐。

### Deferred
