## 缺陷与根因

发现来源：V1.8 Cloudflare Preview acceptance。反馈详情在 768px、NEW 状态且全部六个操作可用时，`document.documentElement.scrollWidth = 810`，标题近乎竖排，最右侧“关闭”按钮越界。弹窗退出后仍可复现。

共享 `PageHeader` 在 768px 仍采用桌面横向布局，actions 使用 `flex-shrink: 0`。侧栏与页面留白减少可用空间，操作区占满甚至超过剩余宽度，标题区被压缩。原测试未固定覆盖这一完整动作组合，不能仅依赖已有全页面 smoke。

## 修复与范围

仅改变 `frontend/src/components/ui/PageHeader.vue` 的 scoped CSS：

- Mobile/Tablet（≤1199px）标题、状态与操作区上下排列，两个区域均占可用宽度，按钮自然换行。
- Desktop（≥1200px）保持横向布局；父 flex 允许换行，标题以 `20rem` basis 参与分配，操作区可收缩且不超过父宽度。
- Tablet 覆盖 text 的 flex basis，避免 column 模式出现 20rem 的无意义纵向空白。
- 标题/eyebrow 既有长文本换行保留，description 增加长 token 换行。
- 不使用 overflow hidden、裁剪、隐藏按钮、CSS order 或页面特例。

Props `title / description / eyebrow` 与 slots `eyebrow / status / meta / actions` **UNCHANGED**；按钮 DOM、业务事件与顺序未修改。
