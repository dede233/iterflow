# 版本入口与流程精简（2026-11-04）

用户在 Issue #4 本地提交 `4912afb` 后追加三项反馈，并确认需求入口只创建版本并关联，稍后发布；版本自动汇总进度，开发和验收只在需求上操作。本轮仍为本地开发，不推送、合并、部署或访问真实数据库。

## 规则

1. 需求详情提供“创建版本”，默认带入可编辑的版本名称，提交版本信息和需求当前revision。版本创建、需求关联、revision及审计在同一事务完成；失败不留下空版本。已有版本、已上线/取消、无权限、范围外、旧revision不得绕过既有关联规则。不自动发布或迁移已有版本。
2. 重复版本号返回独立业务409及字段信息，提示具体版本号已存在、可更换版本号或使用已有版本；不返回不可见版本详情。表单保留输入并定位版本号，不误报为并发编辑冲突。数据库唯一约束仍防止并发创建。
3. 版本页面移除“开始开发、提测、待发布、退回测试”等重复阶段按钮，保留清单管理、发布检查/发布及取消版本。清单中的需求操作仍操作同一需求流程，不建立第二套确认或验收记录。
4. 版本进度按全量有效关联需求自动派生，返回、列表筛选和统计使用同一规则；不因读取而写数据库，也不把派生值写回ORM实体触发隐式更新。已发布、已取消版本保持真实终态，历史非终态存储字段仅用于兼容。

| 关联需求 | 版本汇总 |
| --- | --- |
| 无有效需求 | 规划中，不可发布 |
| 至少一条，全部DONE且当前内容已确认/符合原历史完成兼容规则 | 待发布 |
| 全部TESTING或DONE，但尚不满足发布条件 | 测试中；包括完成后内容需要重新确认 |
| 已有开发/测试/完成工作，仍混合其他未完成项 | 开发中 |
| 其余尚未开始工作 | 规划中 |

暂停/取消需求仍计入有效清单并阻止发布，不能静默跳过；异常ONLINE需求也不取得新的发布资格。暂停来源属于已开始阶段时汇总为开发中。

READY为自动汇总的可发布提示，不再冻结清单。添加、移出、迁移仍执行原权限、双revision和审计，修改后立即重新汇总；仅RELEASED/CANCELED冻结。取消版本保留原权限及审计，所有未发布阶段可取消。旧客户端手动推进/退回版本阶段返回明确409，引导操作需求。

## 发布与兼容

发布检查只读，正式提交在既有版本→需求锁序内重新检查全部有效需求、当前内容确认及版本revision，再执行同一个Release/版本/需求/反馈/通知事务。只有一次成功发布可进入RELEASED与ONLINE。列表的全局汇总不扩大用户对需求详情、数量和阻塞详情的数据范围。

旧版本、发布历史和审计不回填伪造的开发/验收操作；不改历史契约。当前开发契约先更新，前后端同步实现。相对`4912afb`不追加migration；分支仍含Issue #4的`0014_issue4`/`mysql57_0012`，后续部署须先按既有升级文档备份与迁移。

API/Web须配套升级或回退：旧API不会执行新的创建关联字段，不能混用新版入口与旧API。回退应用不恢复或覆盖数据库；历史非终态存储值可能与当前需求进度不同，旧界面需按原手动流程管理，已发布记录保持不变。
