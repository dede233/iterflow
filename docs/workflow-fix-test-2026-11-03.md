## 修复行为

- 提交验收前展示缺少有效验收人、设计未完成及内容确认失效的阻塞项，不能打开可提交的状态弹窗。缺人时可直接打开对应人员选择；无编辑权限时提示联系有权限成员。保存人员保留其他环节，仍需显式执行流程动作。
- 开始开发、提交验收、验收通过、退回、恢复及重新开发根据实际操作人判断是否代操作；代操作原因标为必填并在发送请求前检查。
- 反馈受理读取同一协作人员组件的结果，指定接收人可正常受理；合法管理员代受理显示原因输入框；其他人获得指定接收人受理的说明。加载失败或 revision 不一致时不推断受理资格。历史无接收人的反馈保留正常受理兼容。
- 操作失败在原表单展示后端具体说明并保留输入，不自动重放请求；仅上述表单关闭泛化的 403 toast，其他 API 的默认权限错误不变。

## 本地验证

初轮全套前端单测 394 项通过，TypeScript/Vite 构建通过。后端服务规则及需求、反馈、版本、发布 API 回归 123 项通过，使用新建临时 SQLite 与不连接数据库的服务逻辑测试，未访问真实数据库。

浏览器首轮 42 项中 40 项通过；2 项失败均为定位器未匹配 Element Plus 必填标签中的星号。实际输入框和必填标记均存在，已保留首次日志并修正为含必填文案的定位；新增普通接收人／历史无接收人兼容用例后，46 项全部通过（含人员卡片六种宽度、页面与抽屉）。复查补充反馈 revision 一致性后，反馈相关 8 项再次通过。

同一 Agent 复查（非独立审查）：保留实际指定人员与代操作原因，不以管理员资格跳过未分配人员；只按后台已有条件阻止无效动作；人员保存不自动推进需求。复查还补充反馈协作 revision 一致性，避免使用旧协作人员推断新状态受理资格，正常同 revision 重读不清除已加载人员。
